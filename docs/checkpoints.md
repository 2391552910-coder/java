# 6 次独立实践挑战

先不使用 AI、参考解和搜索；自己的笔记可以作为第二轮补救。计时用于发现瓶颈，不作强制淘汰线。未通过就回对应课程重练。

## A：语言与对象（01–04，45–60 分钟）

**任务：** 重新写内存工单仓库，增加最多重开两次的规则。

**验收：** 空白标题拒绝；重复 ID 不覆盖；第三次重开失败；按 ID 排序只返回 OPEN。运行检查并说明列表与元素的可变性。

**讨论：** 为什么 HashMap 不是线程安全？你在哪里保护业务状态？

## B：HTTP 与分层（05–06，60–90 分钟）

**任务：** 创建、查询和关闭工单接口，注入仓库而不在控制器直接 new。

**验收：** 正常请求、错误输入、缺失资源、重复关闭有明确状态码与响应。测试能替换存储，不启动真实模型。

**讨论：** 单例 Service 为什么不能保存当前用户字段？

## C：持久化与竞争（07–08，90–120 分钟）

**任务：** 工单与事件同事务写入；两个相同旧版本的更新竞争。

**验收：** 实际数据库中途失败两表都回滚；两个更新只有一个成功；用独立查询确认提交状态，不依赖测试自动回滚掩盖错误。

**讨论：** 同类自调用事务方法有什么问题？为什么远程 HTTP 不在本地回滚范围？

## D：权限与缓存（09–10，60–90 分钟）

**任务：** 两个用户各一个知识库；元信息缓存，权限独立检查。

**验收：** A 改 URL 无法访问 B；改名后行为符合陈旧约定；Redis 不可用时不会无限等待或无限回源。

**讨论：** 复现旧值回填竞态。怎样避免缓存把 A 的授权结果给 B？

## E：AI 任务协议（11–13，90–120 分钟）

**任务：** 使用模拟 Python 服务，支持任务受理、查询、重复请求和流式进度。

**验收：** 同键同内容返回原任务；同键不同内容冲突；超时结果未知时能查询；跨字节块解析 SSE 正确；断连后资源行为明确。

**讨论：** worker 在外部执行成功、写结果之前崩溃，你怎样处理？如果下游无幂等能力，有什么限制？

## F：交付（14–15，多次实践）

**任务：** 有界并发、可复现启动和三分钟演示。

**验收：** 过载返回明确结果；另一台电脑可启动；正常、越权、超时恢复都有证据；测量数据注明环境与样本。

**讨论：** 真实瓶颈是什么？哪个优化可以用前后同条件数据证明？

## 记录方式

每次记录：独立完成部分、卡住位置、提示级别、运行证据、下一次变式。不要只写“已学会”。
