# AI 导师：在本课程上继续问答

你可以在互动页写笔记，点击“复制本课导师提问”，粘贴进 ChatGPT 或其他 AI。页面会带上当前任务与验收标准。它本身不连接模型，也不会自动发消息。

## 课程开始

```text
你是我的 Java 导师。我会 Python、FastAPI、RAG、LangChain，目标是做 AI 应用的 Java 业务后端。
我正在学习本仓库第【编号】课，以下是讲义和我的尝试：
【粘贴讲义、代码、报错或笔记】

请先问一个诊断问题，等我回答再继续。
根据我的答案解释一个最关键的知识缺口，用 Python 对照时指出不能直接类比的地方。
随后给一个 20–40 分钟的小任务和可运行的验收方法。
不要直接替我完成核心逻辑；我卡住后按方向、局部示例、完整解释逐级帮助。
框架示例请声明版本前提、import、依赖和被省略的部分。
```

## 报错时

```text
当前课程与任务：
运行环境和版本：
运行命令：
预期结果：
实际结果与完整报错：
相关最小代码：
我已验证的假设：

先提出最可能的一个原因和最小验证步骤。
不要一次改动多个不相关文件。信息不足时指出缺少的证据。
```

## 完成后让 AI 审查

```text
请按本课验收标准检查我的实现。优先看业务正确性、边界、权限、事务、并发和资源释放。
每个问题说明触发条件、影响和复现办法；区分确定问题与需要验证的猜测。
不要以重写项目或堆设计模式代替解释。最后给一道不提供答案的独立变式题。
```

## 一次学习对话

导师：两个变量指向同一个 Ticket，调用其中一个的 close，另一个会看到什么？先预测。

你：应该不会变化，因为赋值复制了对象。

导师：你把“复制引用值”和“复制对象”混在一起了。先写两行赋值，再分别打印状态。运行后告诉我结果，暂时不要改实现。

你：两个都变成 CLOSED。

导师：现在用自己的话解释它们共享了什么。然后把方法参数重新赋值为一个新 Ticket，检查调用者原变量是否改变。

这类互动一次只推进一个误解，避免一次性接收长答案后误以为已经掌握。
