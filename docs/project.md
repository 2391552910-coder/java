# 贯穿项目：AI 知识库与工单助手

## 目标与范围

用户登录后管理授权知识库，提交问题，查看有引用的建议，确认后创建工单。Java 负责用户、权限、事务与任务管理；Python 负责文档处理、RAG 与 Agent。先做单体 Java 服务加一个 Python 服务。

这是待实现的项目规格，不代表仓库已有运行代码。

## 建议实体

User、KnowledgeBase、KnowledgeBaseMember、Document、AiTask、Ticket、TicketEvent。每个实体记录必要的创建和修改时间。AiTask 保存请求 ID、状态、错误摘要；Ticket 保存版本号用于并发更新校验。

## 建议接口

| 方法与路径 | 作用 |
|---|---|
| POST /api/knowledge-bases | 创建知识库 |
| GET /api/knowledge-bases | 查看有权限的知识库 |
| POST /api/knowledge-bases/{id}/documents | 登记文档并创建处理任务 |
| POST /api/tasks | 创建 AI 任务，支持幂等请求 ID |
| GET /api/tasks/{id} | 查询本人有权查看的任务 |
| POST /api/tasks/{id}/cancel | 请求取消任务 |
| POST /api/tickets | 经用户确认创建工单 |
| PATCH /api/tickets/{id}/status | 带版本号修改状态 |

接口字段、错误码和状态转换由实现时明确并记录。Java 验证权限后，向 Python 传递经过验证的检索范围；Python 也必须限制检索范围，不能仅在生成答案后过滤。

## 分阶段交付

- V0：纯 Java 内存工单程序。
- V1：Spring Boot 接口与参数校验。
- V2：数据库、事务、并发修改保护。
- V3：认证、数据权限、缓存。
- V4：AI 任务协议、幂等、超时、故障恢复。
- V5：部署、测试报告与演示说明。

## 最终验收

- [ ] 正常流程可演示，文档引用可追溯。
- [ ] 越权访问被拒绝，包括任务结果与文档检索。
- [ ] 工单及事件写入失败时一起回滚。
- [ ] 重复提交不重复生成工单或任务。
- [ ] 并发状态更新有明确冲突结果。
- [ ] Python 服务关闭或超时时，Java 在规定时间内结束等待。
- [ ] 已受理但响应丢失时，可凭请求 ID 查询而非盲目重做。
- [ ] 进程重启后，未完成任务有可解释的恢复或失败策略。
- [ ] 流式客户端断开后，释放资源并按约定取消或保留任务。
- [ ] README 可复现部署；环境文件只有占位值。
- [ ] 性能与质量数据来自实际测试，包含测试条件。

## 面试复盘问题

1. 为什么需要 Java 和 Python 两个服务？是否值得增加部署复杂度？
2. 数据库事务为何不能自动覆盖远程调用？
3. 幂等键由谁生成，在哪里唯一，保存多久？
4. 缓存失效和权限变更如何避免错误访问？
5. 工具超时重试为何可能造成重复副作用？
6. 一个最难复现的故障是什么，如何定位和验证修复？
