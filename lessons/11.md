# 11 · 调用 Python：超时不是取消，也不证明失败

第 9 周 · 首次讲解与小练习约 75 分钟，项目实践另计。

AI 调用慢且可能失败。把“发一个 HTTP 请求”升级为有时间预算、有身份、有可观测性的服务协作。

## 区分三种时间

连接超时限制建立连接的等待；请求超时限制一次调用的等待范围；任务业务截止时间限制任务还值得执行多久。具体客户端的响应体、流式读取超时语义要单独确认。给每个调用设置合理预算，记录排队、连接和下游执行耗时，不能只看总耗时。

## 未知结果要显式表达

Java 超时只说明自己没在规定时间拿到结果；Python 可能尚未执行，也可能已执行成功。取消本地 Future 也不保证远程停止。对有副作用操作，下一步应查询任务状态或按相同幂等键重试，不能换一个新键重复执行。对不确定结果不要伪装成“确定未执行”。

## 协议先行

定义 requestId、taskId、调用者范围、状态和错误分类。短请求可同步返回；耗时任务先受理返回 taskId，再查询或订阅状态。服务间身份不要依赖用户可伪造的头；密钥放环境配置，并明确下游怎样校验。日志用 requestId 串联，错误信息不含密钥和完整提示词。

## 联系你的 Python 经验

可以对照 Python httpx 的连接与请求超时，但各客户端的细分选项不同。不要把一个 timeout 数字当成对所有阶段和远程生命周期的完整控制。

## 代码拆解

```java
HttpClient client = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(2))
    .build();
HttpRequest request = HttpRequest.newBuilder(
        URI.create("http://localhost:8000/health"))
    .timeout(Duration.ofSeconds(5))
    .GET().build();
HttpResponse<String> response = client.send(
    request, HttpResponse.BodyHandlers.ofString());
if (response.statusCode() != 200) {
    throw new IllegalStateException("AI服务状态异常");
}
```

JDK HTTP 客户端片段，需要 java.net.http、java.net.URI、java.time.Duration 的 import；send 还需处理 IOException 和 InterruptedException。客户端应复用，处理中断时保留中断语义。本片段只做 health GET，不包含完整鉴权或任务协议。

## 自测

### 1. Java 等待超时，能证明 Python 没有创建任务吗？

1. 能
2. 不能，可能已成功但响应丢失
3. 只要是 POST 就能

<details>
<summary>答案与原因</summary>

答案：2。传输失败与业务执行结果不是一回事。

</details>

### 2. 对创建任务超时，优先采用哪种恢复思路？

1. 换新 requestId 无限重试
2. 查询原任务，或按相同幂等键重试
3. 直接向用户声称没有执行

<details>
<summary>答案与原因</summary>

答案：2。恢复必须关联原操作，避免重复副作用。

</details>
