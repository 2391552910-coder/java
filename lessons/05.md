# 05 · Spring 与依赖注入：从手动组装到容器管理

第 4 周 · 首次讲解与小练习约 60 分钟，项目实践另计。

Spring 先看成负责组装对象的容器。理解这一步，再读注解才不会变成“加上就能跑”的记忆题。

## 手动注入已经是依赖注入

new TicketService(repository) 由调用者提供仓库，服务本身不负责选择具体实现。Spring 容器负责创建对象、查找依赖并调用构造器。被容器管理的对象称为 Bean。@Service、@Repository、@Component 标记组件；包扫描范围之外的类不会仅因加了注解就自动出现。

## 生命周期与共享状态

常见 Spring Bean 默认是 singleton，即同一个容器中复用一个实例。它不意味着 JVM 全局只有一个，也不保证线程安全。把“当前用户”存在单例 Service 字段里会串请求；请求数据应通过参数或合适的请求上下文传入。服务可以共享无状态行为，但对共享可变数据必须设计并发控制。

## 先保持边界清晰

Controller 接收 HTTP，Service 执行业务，Repository 存取数据。不是每个函数都必须穿越三层，但事务与业务规则不要散落在控制器里。构造器注入让必需依赖明确，也让没有 Spring 的单元测试容易构造服务。如果出现循环依赖，先检查职责拆分，不要直接用延迟注入掩盖设计问题。

## 联系你的 Python 经验

FastAPI Depends 与 Spring 注入都能提供依赖，但缓存、作用域和对象生命周期不能直接等同。先明确“谁创建、共享多久、谁关闭资源”。

## 代码拆解

```java
@Service
class TicketService {
    private final TicketRepository repository;
    TicketService(TicketRepository repository) {
        this.repository = repository;
    }
    Ticket get(long id) {
        return repository.findById(id)
            .orElseThrow(() -> new TicketNotFound(id));
    }
}
```

这是 Spring 项目中的示意片段，需要对应接口与异常类。只有一个构造器时可以省略 @Autowired。final 表示字段引用不重新赋值，不会自动使 repository 对象线程安全。

## 自测

### 1. Spring 默认单例 Service 自动线程安全吗？

1. 是，容器负责全部同步
2. 不是，共享可变状态仍需控制
3. 只要字段都是 private 就安全

<details>
<summary>答案与原因</summary>

答案：2。作用域只描述对象复用范围，不负责保证业务操作原子性。

</details>

### 2. 构造器注入的核心作用是什么？

1. 隐藏全部依赖
2. 明确依赖并交由外部提供
3. 自动让所有方法变成异步

<details>
<summary>答案与原因</summary>

答案：2。它明确对象成立所需要的合作对象。

</details>
