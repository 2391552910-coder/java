# 02 · 对象与接口：让业务规则有自己的位置

第 1 周 · 首次讲解与小练习约 75 分钟，项目实践另计。

如果 Controller、脚本和工具调用都能直接把工单改成任意状态，业务规则很快会失去一致性。今天把规则放回对象，并用接口隔离存储方式。

## 字段不是随意修改的字典

对象把数据与有效操作组织在一起。private 字段限制外部代码直接改状态；通过方法执行合法转换。例如 OPEN 可以关闭，CLOSED 不能重复关闭。构造器负责建立合法初始状态。封装的目的不是机械地给每个字段生成 getter/setter，而是减少无效状态的入口。

## 接口定义合作方式

TicketRepository 接口声明 findById 和 save，使用者依赖这个约定，不必知道数据来自内存还是数据库。TicketService 接收一个实现该接口的对象，这就是依赖注入的朴素形式，不需要 Spring 才能使用。测试时可以注入内存实现。只有一个实现且没有替换需求的类，也不必强行配接口。

## 引用与不可变数据

把对象赋给另一个变量会复制引用，不会复制整个对象。Java 参数传递始终是值传递：对象参数传入的是引用值的副本，因此能修改对象内部状态，但重新赋值参数不会改变调用者变量指向。record 适合传输数据，自动提供访问器与值比较，但内部引用的集合不因此自动深度不可变。

## 联系你的 Python 经验

可以把接口理解为显式声明的合作契约，和 Python Protocol 的用途有相似之处；Java 会在编译时检查具体实现。不要把 Java 每个类都理解成必须设计复杂继承树。

## 代码拆解

```java
enum Status { OPEN, CLOSED }

final class Ticket {
    private final long id;
    private Status status = Status.OPEN;
    Ticket(long id) { this.id = id; }
    long id() { return id; }
    Status status() { return status; }
    void close() {
        if (status != Status.OPEN) {
            throw new IllegalStateException("工单已经关闭");
        }
        status = Status.CLOSED;
    }
}
```

final 字段 id 只能赋值一次；status 通过 close 修改。枚举可以用 == 比较。例子是领域对象片段，不是带 main 的独立程序。

## 自测

### 1. Ticket b = a; 后修改 a 对应对象的状态，b 会看到变化吗？

1. 会，它们指向同一个对象
2. 不会，赋值会深拷贝
3. 仅用了 Spring 才会

<details>
<summary>答案与原因</summary>

答案：1。赋值复制引用值，不复制对象。

</details>

### 2. 把存储依赖作为构造器参数传入，最直接的好处是什么？

1. 自动开启数据库事务
2. 可以在测试中替换存储实现
3. 自动避免全部线程安全问题

<details>
<summary>答案与原因</summary>

答案：2。显式依赖可由调用者提供，也容易注入测试替身；事务和线程安全需要独立设计。

</details>
