# 15 · 交付与复盘：让别人能启动，也能验证

第 12 周 · 首次讲解与小练习约 90 分钟，项目实践另计。

最终成果不是一张成功截图，而是另一台电脑能复现运行、正常流程与故障行为，并知道系统仍有什么限制。

## 部署是明确依赖

Java、Python、数据库、Redis 各有配置、端口和生命周期。容器里的 localhost 指向当前容器，Java 访问 Python 通常使用 Compose 服务名。启动顺序不等于应用已就绪，要有健康检查或重试；数据库使用数据卷，密钥由环境配置提供，仓库示例只有占位值。

## 验收覆盖失败

至少验证正常提问建单、越权访问、第二次写入失败回滚、同键重复请求、Python 超时、流式断连、重启后的未完成任务。模拟模型可以先稳定覆盖工程行为，真实模型再验证回答质量与工具决策。P95、错误率和完成率都需要说明样本、并发、硬件、模型和测量范围。

## 口头解释决定是否掌握

能从请求进入一路解释身份、校验、事务、AI 调用和结果返回，说明每个边界为何存在。把最难的故障写成“现象—假设—证据—修复—复验”。没有测量的提升不要写进简历。课程结束后再选 Spring AI 或消息队列，针对真实缺口补，而不是继续堆技术名词。

## 联系你的 Python 经验

Python 经验是你的优势。最终目标是让两种语言的服务围绕明确契约协作，而不是证明自己能用 Java 重写每一段 Python。

## 代码拆解

```yaml
# Compose 网络内的配置示意，不是完整部署文件
services:
  java-api:
    environment:
      AI_BASE_URL: http://python-ai:8000
  python-ai:
    environment:
      MODEL_MODE: mock
```

实际还需要镜像或 build、端口、依赖、数据卷和健康检查等配置。这里用服务名解释容器网络，不伪装为开箱即用部署。

### 1. Java 容器中 localhost:8000 默认指向哪里？

1. Python 容器
2. 当前 Java 容器本身
3. 宿主机所有服务
