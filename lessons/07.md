# 07 · SQL 与 MyBatis：先保证查询正确，再谈索引

第 6 周 · 首次讲解与小练习约 90 分钟，项目实践另计。

把工单放进数据库后，数据会跨进程、跨请求保存。正确的数据约束比应用里的一次 if 判断更可靠。

## 最小表设计

ticket 表至少有 id、owner_id、title、status、version、created_at。NOT NULL、主键和唯一约束表达数据库层不允许破坏的规则。request_id 若用于幂等，应与调用者范围一起形成唯一约束。不要先用 SELECT 查重再 INSERT 就认为不会重复：两个请求可能同时查到不存在。

## SQL 参数绑定

MyBatis 的 #{id} 通常生成预编译参数，不能把输入当作 SQL 结构执行；${} 是文本替换，外部输入直接放进去有注入风险。ORDER BY 的列名不能像普通值一样随意参数绑定，先把用户选项映射为固定白名单。Mapper 返回实体后，服务仍要按权限筛选，不能查到就返回。

## 索引从查询出发

常见查询是 WHERE owner_id=? AND status=? ORDER BY id LIMIT ?，可以尝试联合索引(owner_id,status,id)，再用 EXPLAIN 和实际数据验证。索引增加写入和存储成本，不是越多越好。无 ORDER BY 的分页没有可靠顺序；大 OFFSET 可能昂贵，后续可用最后一个 id 做游标分页。

## 联系你的 Python 经验

如果你在 Python 中使用 ORM，也仍要理解实际 SQL。Java 换了框架并不会改变数据库约束、事务和索引的原理。

## 代码拆解

```sql
CREATE TABLE ticket (
  id BIGINT PRIMARY KEY,
  owner_id BIGINT NOT NULL,
  title VARCHAR(200) NOT NULL,
  status VARCHAR(20) NOT NULL,
  version BIGINT NOT NULL DEFAULT 0,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_ticket_owner_status_id
  ON ticket(owner_id, status, id);

SELECT id, title, status, version
FROM ticket
WHERE owner_id = ? AND status = ?
ORDER BY id
LIMIT ?;
```

这是 MySQL 风格练习 SQL，ID 生成由调用方暂时提供；并未承诺 VARCHAR 的数据库字符语义与 Java length 完全一致。MyBatis XML 中将值位置的 ? 写为 #{ownerId} 等参数表达式。

## 自测

### 1. 外部传入的标题应怎样传给 MyBatis 查询？

1. 用 ${title} 拼接
2. 用 #{title} 绑定值
3. 先删除所有空格再拼接

<details>
<summary>答案与原因</summary>

答案：2。预编译参数把值与 SQL 结构分开；手动删字符不是可靠注入防护。

</details>

### 2. 先 SELECT 发现没有，再 INSERT，能保证并发不重复吗？

1. 能
2. 不能，还需要数据库唯一约束等并发机制
3. 只有 Java 能保证

<details>
<summary>答案与原因</summary>

答案：2。两个请求可能同时通过查询，数据库约束才负责最终竞争裁决。

</details>
