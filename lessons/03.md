# 03 · 集合与泛型：实现内存版工单仓库

第 2 周 · 首次讲解与小练习约 75 分钟，项目实践另计。

把零散对象组织成可查询的仓库。先掌握集合选择和数据所有权，再写 Stream；代码短不等于更容易维护。

## 根据访问方式选集合

ArrayList 适合顺序遍历，按下标访问快；按工单 ID 查找用 HashMap<Long, Ticket> 更直接。HashSet 用来去重。Map 的键依赖 equals/hashCode，作为键的对象如果参与散列计算的字段被修改，会导致难以理解的查找问题。Long 等不可变键能减少这类风险。HashMap 不保证遍历顺序。

## 泛型与空结果

Map<Long, Ticket> 让编译器限制键和值的类型，读取时通常不需要强制转换。Map.get 找不到时返回 null，本课选择在仓库层返回 Optional<Ticket>，明确“可能不存在”；不要到处 get() 而不处理为空。Optional 不是所有字段都要套上的装饰。

## 别泄露内部集合

直接返回内部 values 视图可能让调用者删除仓库数据。List.copyOf 提供不可修改的列表快照，但里面 Ticket 若可变仍可能被修改；不可修改列表不等于深拷贝。真正跨边界返回时可转换成不可变 DTO。Stream 的 filter/map/toList 适合清晰的数据流水线，涉及复杂分支时普通循环更直观。

## 联系你的 Python 经验

Map 类似 dict，但键值类型在编译期固定。List.copyOf 类似做一个受限的浅快照，不是 Python deepcopy。

## 代码拆解

```java
import java.util.*;

final class MemoryTicketRepository {
    private final Map<Long, Ticket> data = new HashMap<>();
    void save(Ticket ticket) { data.put(ticket.id(), ticket); }
    Optional<Ticket> findById(long id) {
        return Optional.ofNullable(data.get(id));
    }
    List<Ticket> findOpen() {
        return data.values().stream()
            .filter(t -> t.status() == Status.OPEN)
            .toList();
    }
}
```

依赖上一课的 Ticket 与 Status。findOpen 返回列表不能增删，但对象本身仍然可变。此仓库只用于单线程练习，不宣称线程安全。

## 自测

### 1. List.copyOf(tickets) 能保证列表中 Ticket 对象完全不可变吗？

1. 能，自动深拷贝
2. 不能，只限制列表结构修改
3. 能，只要列表来自 HashMap

<details>
<summary>答案与原因</summary>

答案：2。元素引用仍然指向原对象；集合的不可修改性与元素不可变性是不同问题。

</details>

### 2. 需要经常按工单 ID 查询，优先考虑什么？

1. 每次排序全部数据
2. HashMap<Long, Ticket>
3. 只保存打印后的字符串

<details>
<summary>答案与原因</summary>

答案：2。键值映射直接表达按 ID 查询的需求。

</details>
